# ADR-0011: Management API conventions and OpenAPI

Status: Accepted (2026-11-20); parts superseded by [ADR-0015](0015-api-conventions-amendments.md): the 409 code for a stale version, DELETE versioning, the partial-update convention and the paging-stability wording

## Context

Every configurable object (commitments, categories, rules, tokens, settings) is managed through the Management API, which the UI, the Go client and CLI (M2), the Terraform provider and the MCP server all use. They need one set of conventions before the first real resource lands: base path, identifiers, lists, filters, concurrency, errors and a machine-readable description. Decision D17 chose optimistic concurrency (version/ETag, 409 with reconciliation). ADR-0006 left two gaps: a 405 on an API route came out as a 404 `not_found`, and the envelope had no room for conflict details. No authentication exists yet (tasks A1-A4).

## Decision

1. **Base path and version.** The API lives under `/api/v1` (`httpapi.APIPrefix`). `info.version` in the OpenAPI document is semantic; its major version matches the path (tested). A backwards-incompatible change gets `/api/v2`; additions do not.
2. **Identifiers** are ULIDs (`resource.NewID`): 26 upper-case Crockford base32 characters, made once at creation, stable for the life of the object and never reused or changed. Only the canonical spelling is accepted (`resource.ValidID`, and `store.IDCheck` in SQL), so one object has exactly one ID string. **No type prefix**: the URL already names the type, the Terraform provider and the MCP server always know which collection they address, and a prefix would add parsing and a second form to validate. The cost is that an ID seen out of context does not say what it names. ULIDs show creation time to the millisecond; that is acceptable for a single-household instance. API tokens keep their own `ldgr_` prefix (A4); they are secrets, not identifiers.
3. **Spec-first, written by hand, no code generation.** `internal/httpapi/openapi.yaml` (OpenAPI 3.1) is the contract. It is embedded and served at `GET /api/v1/openapi.yaml` and `GET /api/v1/openapi.json` (converted once at first use). Handlers use the standard `net/http` mux and `httpapi` helpers. Every `/api/v1` route is registered in one function, `httpapi.RegisterAPI`, and **`TestOpenAPIContract`** (part of `go test ./...`, so of CI) fails when a registered route is not documented or a documented operation is not registered. The same check (`httpapi.CheckContract`) requires a unique `operationId`, declared path parameters, resolvable local `$ref`s and the shared `Error` default response on every operation, and refuses `{name...}` and `{$}` wildcards in API routes. Another test keeps the document's error-code enum equal to the codes `httpapi` defines.
4. **API routing.** `Server.Handle` sends every pattern under `/api` to a separate API mux; such a pattern must name a method and must not name a host. An unmatched API request gets the error envelope: 404 `not_found`, or 405 `method_not_allowed` with the `Allow` header the mux computed (this replaces the plain-text 405 and the 404-for-405 described in ADR-0006). `/api` paths never reach the UI. Unmatched 404 and 405 requests keep the bounded `unmatched` route label (ADR-0009). `GET` routes also answer `HEAD`.
5. **Lists.** A list returns `{"items": [...], "next_cursor": "<opaque>" | null}` in one fixed, documented order, by default the ID (creation) order. `limit` is 1-200, default 50. `cursor` is the previous `next_cursor`. It is opaque (today base64url JSON holding the last ID and a fingerprint of the filters), and it is refused (400 on `cursor`) when the filters differ, so changing a filter mid-walk can never skip or repeat items silently. Paging is keyset-based (`id > after ORDER BY id LIMIT n+1`), so inserts and deletes between pages do not shift items. There is no total count and no `sort` parameter yet. A list that needs another order extends the cursor with its sort key in its own task.
6. **Filters.** `field=value` tests equality (repeat the parameter for any of several values); `field[op]=value` applies an operator, one of `prefix`, `gt`, `gte`, `lt`, `lte`, where the endpoint declares it in its `httpapi.ListSpec` and documents it. Non-equality filters may appear once. Unknown parameters, undeclared operators, empty values and values the field's check refuses are 400 `validation_failed` naming the parameter. Strictness is deliberate: a misspelt filter on a financial list must fail, not quietly return everything.
7. **Optimistic concurrency (D17).** Every mutable configurable table has `id TEXT PRIMARY KEY CHECK (IDCheck)` and `version INTEGER NOT NULL DEFAULT 1 CHECK (version >= 1)`. Changes go through `store.UpdateVersioned` / `store.DeleteVersioned`: `UPDATE ... SET ..., version = version + 1 WHERE id = ? AND version = ?` inside the write transaction. When no row changed, a second read in the same transaction tells `resource.ErrNotFound` (404) from `*resource.VersionConflictError` (409). `TestMutableTablesAreVersioned` checks every table in the migrated schema. Tables that are not mutable configuration (bank facts, append-only logs, internal bookkeeping) go in its `unversionedTables` list with a reason; today that is `schema_migrations` and `settings`.
   - Responses carry `version` in the body and the strong ETag `"<version>"`.
   - **A change or delete must name the version it is based on**, in `If-Match` or in the body's `version` field (useful for clients that cannot set headers). Without either it is **428 `precondition_required`** (a new code; codes only grow). If both are given they must agree. `*`, weak tags and lists are 400. Creates need no version.
   - A stale version is **409 `conflict`** (D17), not the 412 that RFC 9110 suggests for a failed `If-Match`: D17 chose 409, and one status for "someone else changed this" is simpler for clients. The response carries the current ETag and `"reconciliation": {"current_version": n, "current": {...}}`. `current` is the object as it is now, so the client can show the difference, merge and retry. A handler includes it only for a caller allowed to read the object (`httpapi.VersionConflict(v, nil)` sends the version alone). A bare `VersionConflictError` passed to `WriteError` sends the version alone.
   - Making the version mandatory, not optional, prevents lost updates by default. The Terraform provider, the CLI and the MCP tools all read before they write, so sending the version costs them nothing.
8. **Errors.** The ADR-0006 envelope is unchanged except for one additive optional member, `reconciliation`, sent only with a version conflict. `httpapi.WriteError` also maps `resource.ErrNotFound` to 404.
9. **Authentication hook.** `httpapi.WithAPIMiddleware` wraps every handler registered under `/api`, after route matching (`r.Pattern` is set, so grant checks can look a route up by its pattern), and never runs for the unmatched 404/405 answers. A1-A4 plug authentication and grants in there. Until they land, the API is unauthenticated, as every pre-auth slice is. The OpenAPI document itself is the same file as in the public source repository; A1 decides whether it stays readable without a session.
10. **Example resource.** `internal/apiexample` is an internal example, clearly marked, that shows everything above end to end against SQLite: create, get, a list with cursor pagination and `kind` / `name[prefix]` filters, and change and delete with ETag, If-Match, 409 with reconciliation, 428 and 404, plus a concurrency test where exactly one of eight writers based on the same version wins. Its OpenAPI paths are merged into the published document only in its own contract test. `ledger serve` does not register it, its table is not in the embedded migrations, and it is not part of the published API, so it never becomes a v1 commitment. No product resource is invented here: the first real ones come with C1, O2 and A1.

## Why

- **Spec-first, hand-written** keeps the public contract readable, reviewable and in one file, which the Terraform provider and M2's client are built against. Code generators for Go servers (for example oapi-codegen) would add modules and generated code to a deliberately small dependency set (ADR-0009), and the `net/http` mux already does method and wildcard routing. **Code-first** (deriving the document from handlers) would need annotations or reflection that Go does not have built in, and tends to produce a document shaped by the implementation rather than by clients. The cost of writing it by hand is drift, which the contract test catches for routes. Request and response *schemas* are not checked automatically yet (see Consequences).
- **Keyset cursors** stay correct while data changes and cost the same on every page; offsets do neither.
- **A separate API mux** is the smallest change that gets ServeMux's real 405 detection (with `Allow`) without the UI catch-all swallowing it.

## Consequences

- Each resource task must: register its routes in `RegisterAPI` (or the contract test fails), document them in `openapi.yaml` with the shared parameters, headers and `Error` response, follow the `id`/`version` convention (or list the table in `unversionedTables` with a reason), and return `version` and `ETag`.
- `CheckContract` checks structure, not full OpenAPI 3.1 validity, and does not validate request or response bodies against the schemas. A stricter schema check (an OpenAPI validator in tests, or M2's generated client exercising every operation) is left to M2 and the resource tasks.
- Conditional GET (`If-None-Match`/304), `sort`, total counts and other list orders are not implemented. They are added when a resource needs them.
- The reconciliation body exposes the current object. Once grants exist (A1), handlers must send `current` only to callers allowed to read it.
- `If-Match` deviates from RFC 9110's 412 by design (D17). Clients written against generic HTTP libraries must treat 409 `conflict` with `reconciliation` as the precondition failure.
- `resource.NewID` now also generates request and job IDs (`logging.NewULID` delegates to it), so there is one ULID encoder.
